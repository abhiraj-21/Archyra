# frontend/CLAUDE.md

Frontend-specific guidance. System-wide architecture, API standards and the roadmap are in the root `CLAUDE.md` and `Architecture.md`. The build spec is `spec/ui/spec-ui.md`; design decisions are in `DESIGN-NOTES.md`.

## Status

Built against the live backend (V0.1 and V0.5 APIs): landing, auth (email/password, Google, GitHub, verification, password reset), dashboard with history and usage, the polling progress view, the repository workspace (Overview, Architecture, Files, Relationships, Ask AI), settings, and the admin area. Ask AI (V1) is built against the real backend; the V2/V3 graph features are shown as "coming soon" and never called.

## Commands

```bash
npm run dev             # Vite on :5173, proxying /api, /oauth2, /login/oauth2 to the backend
npm run verify          # typecheck + lint + check:tokens + unit tests + build + session-boot e2e (keep it green; the e2e part skips without the running stack)
npm run e2e:session     # just the session-boot regression tests (scripts/e2e/session-boot.spec.ts)
npm run e2e             # Playwright against the running app and backend (skips without .env.local creds)
npm run assets:capture  # regenerate src/assets/*.png from the running app (see src/assets/README.md)
node scripts/e2e/probe-api.mjs   # print live response SHAPES (no values) to check src/api/types.ts (includes ai-index and conversations)

npx vitest run src/lib/url.test.ts          # one unit test file
npx vitest run -t "encodeNodeId"            # unit tests by describe or test name
npm run e2e -- -g "admin gating"            # e2e tests by name
```

## Setup

- `VITE_BACKEND_ORIGIN` (default `http://localhost:8080`) is the proxy target; `.env.example` lists every variable. `VITE_*` values ship to the browser: never a secret there.
- The browser only uses relative URLs, so SPA and API share an origin and the `SameSite=Strict` refresh cookie works. The proxy keeps the original `Host` (`changeOrigin: false`) and adds `X-Forwarded-*` (`xfwd`), so the backend builds OAuth redirect URIs on `http://localhost:5173` (checked against the real authorization redirect; `scripts/e2e/auth-flows.spec.ts` guards it). Register `http://localhost:5173/login/oauth2/code/{google,github}` with the providers and always browse via `http://localhost:5173`, never `127.0.0.1`. **Google** can hold several redirect URIs (keep the `:8080` one next to it); a **GitHub OAuth App holds exactly one** callback URL, so it serves the proxy flow or direct `:8080` use, not both (a second OAuth App with its own `GITHUB_CLIENT_ID`/`GITHUB_CLIENT_SECRET` in `backend/.env` covers both). A `redirect_uri_mismatch` is a provider-console setting, not a code defect. In production, serve the SPA and the API on one origin behind a reverse proxy.
- Capture and e2e scripts read test accounts from an untracked `.env.local` (`ARCHYRA_TEST_*`, `ARCHYRA_ADMIN_*`). Use dedicated test accounts, never a real person's.
- `scripts/e2e/ask-ai.spec.ts` (Ask AI: index panels, conversations and `?c=`, failure UIs by route interception; reuses a COMPLETED analysis of the test account and never starts one or asks a question, except the one real-question test that needs `ARCHYRA_E2E_AI=1` because it spends provider quota and one AI_QUERY unit), `scripts/e2e/graph-controls.spec.ts` (scope, dragging; reuses a COMPLETED analysis of the test account that has test code, and only starts one when there is none) and `scripts/e2e/auth-flows.spec.ts` (OAuth `redirect_uri` through the dev proxy; registering the same address twice, opt-in with `ARCHYRA_E2E_REGISTER=1` because it creates an unverified dev account and spends register attempts) run against the real stack. The login endpoint allows 10 attempts a minute per IP, so a spec signs in once and shares the page.
- The register → verify-email e2e test is skipped because mail goes to a real SMTP relay. Pointing the backend at the local MailHog sink described in `backend/README.md` gives a readable dev mailbox.
- `assets:capture` and the analysis e2e test analyse a repository as the test user: each run briefly uses one free analysis (returned on delete or when a re-run replaces the old one).

```
  hooks/       TanStack Query hooks per endpoint, session provider and context, upgrade context
  components/  ui/ (buttons, fields, dialog, chips, locked states), layout/ (AppShell), graph/ (adapter, graphStyles,
               layout worker with dagre, canvas, inspector, legend)
  features/    landing, auth, dashboard, analysis-progress, repository/{overview,architecture,files,relationships,ask-ai},
               usage, upgrade, settings (profile, plan, sign-in methods, password, danger zone), admin, system (boot, 404)
  routes/      router.tsx, guards.tsx

```

## How the pieces fit

- **Session boot** (`hooks/session.tsx`) is the **only** code that hydrates a session on page load: `GET /auth/csrf` → `POST /auth/refresh` (HttpOnly cookie) → `GET /users/me` (seeded into the query cache), as one module-level single-flight promise, so StrictMode's double effects and remounts share it: exactly one `POST /auth/refresh` per page load. It has a hard `BOOT_TIMEOUT_MS` (10 s) that aborts the in-flight auth requests (`abortAuthRequests`) and shows the retry screen (`BootScreen failed`: *Try again* re-runs the boot, *Back to sign in* calls `abandonBoot`); a network failure does the same. `routes/guards.tsx` shows the boot screen until it settles. `/auth/callback` (Google/GitHub return) **never calls refresh**: it waits behind `BootGate`, then goes to the stored return target (`lib/returnTo.ts`) when authenticated, or to `/login?error=oauth_failed` when the boot found no session. Never `queryClient.clear()` and then rely on a refetch while `useQuery` observers are mounted (the original "Opening Archyra" hang: `spec/oauth-login-hydration-and-account-linking/root-cause.md`); clear, then `setQueryData` the new `me`. `api/http.ts` turns a `401 AUTHENTICATION_REQUIRED` into one shared refresh and one retry; `refresh`/`logout` refetch the CSRF token and retry once on `403 CSRF_TOKEN_INVALID` (never on 401). A failed refresh calls `expireSession`, and the guard redirects to `/login?next=…` (a deliberate sign-out goes to plain `/login`).
- **Analysis lifecycle:** `/analyses/:id` polls status (`useAnalysisStatus`, 2 s, stops at COMPLETED/FAILED) and hands over to `/analyses/:id/overview`; the workspace layout redirects back to the progress view while the analysis is not COMPLETED. Result queries take a `ready` flag and stay idle until then.
- **Graph:** the whole graph is fetched once per analysis (`useGraph`, `staleTime: Infinity`) and filtered client-side (the V0.1 `nodeType`/`relationshipType` take one value each). `graph/adapter.ts` produces the visible set, `graph/useLayout.ts` runs dagre in `layout.worker.ts` (cached by visible ids), `GraphCanvas` renders it and fits the connected part. Filters, the selected node and the list view live in the URL (`?nodes=&edges=&node=&view=&scope=&q=`).
- **Sign-in methods (Settings):** `features/settings/SignInMethods.tsx` with `useLinkedIdentities`, `useStartLink`, `useUnlinkIdentity` (`hooks/useLinkedIdentities.ts`). *Link* posts for an intent, checks the returned `authorizationUrl` with `isLinkAuthorizationUrl` and does a full-page `window.location.assign` (never fetch; the backend sets the `link_binding` cookie on that response). The provider returns to `/settings?link=ok&provider=…` or `/settings?link_error=<code>`: the section reads them once (a ref guards StrictMode), shows a toast or a dismissible banner from the fixed allow-list in `lib/errorCopy.ts` (`describeLinkError`; unknown codes get generic copy, the raw value is never rendered), invalidates the identities and `me` queries, and replaces the URL without the parameters (`lib/linkReturn.ts`). *Unlink* is disabled with a visible explanation when it is the only way to sign in (`isLastSignInMethod`); the server's `LAST_LOGIN_METHOD` is handled too. The return is a full page load, so it goes through the normal session boot; there is no special session handling. `ToastProvider`/`useToast` (`components/ui`) is the app's one toast.
- **Password (Settings):** `features/settings/ChangePassword.tsx` with `useChangePassword` (`hooks/useAccount.ts`) → `changePassword` (`api/endpoints/auth.ts`, bearer, **not** an `open` route). It asks for the current password plus the new one twice (`changedPasswordError` in `features/auth/validation.ts`; the server decides). `INCORRECT_PASSWORD` shows on the current-password field, `VALIDATION_ERROR` on the new one, anything else in a notice. **The response is a new session**: the endpoint calls `setAccessToken` with it and the browser replaces the refresh cookie itself, so the user stays signed in here while every other device signs out; the toast says so. When `linked-identities.hasPassword` is false (Google/GitHub-only account) the section shows a pointer to Forgot password instead of the form.
- **Ask AI (`features/repository/ask-ai`):** `AskAiPage` reads the index (`useAiIndex`, polled every 2 s **only while INDEXING**, idle until the analysis is COMPLETED) and switches on `status`: `IndexPanel` for NOT_INDEXED (a *Re-analyze* button that opens the existing `ReanalyzeDialog`, which carries the "conversations are deleted" warning in one place), INDEXING (progress from `embeddedCount/chunkCount`, `aria-live`, a disabled composer), FAILED (the safe `reason`, a free *Retry* when `retryable`, else Re-analyze) and EMPTY; READY shows `ChatWorkspace`. Conversations are listed, created, deleted through hooks (`hooks/useAskAi.ts`); the selected one is `?c=<id>` (left out when none; an unknown or deleted id falls back to the empty state). `useAskQuestion` stays pending until the conversation's messages and `/usage` are refreshed, so the optimistic turn never flickers; the workspace shows the question at once with a polite "Thinking…", disables the composer for that conversation only, and **never loses the typed text**: on every failure it is put back. Failures are handled by `code`: `USAGE_LIMIT_EXCEEDED` replaces the composer with `LimitPanel` (upgrade dialog), `RATE_LIMITED` shows a live countdown from `Retry-After` (`retrySeconds` bounds it), `AI_UNAVAILABLE` and a client timeout (about 75 s) say the question wasn't counted with *Try again*, `AI_NOT_READY` refetches the index, `CONVERSATION_FULL` offers a new conversation. The usage chip reads the real `AI_QUERY` entry (`useAiUsage`, `questionsLabel`), never a literal limit. **Answers are rendered by an in-house renderer** (`lib/askAi.ts` parses blocks and inlines into data, `MarkdownView` builds React elements): no `dangerouslySetInnerHTML`, no HTML from the model, links only for http(s). `[n]` markers with a matching source become superscript buttons that expand and focus the source; a marker with none stays text. A source (`SourceChip`/`SourcePanel`) shows glyph and name, then `file:line–endLine`, the excerpt as text and *Open in graph* (a class or interface directly; a method goes to its owning class through `useNode`; a function has no link). The data-use note sits next to the composer. **The question guide** (`QuestionGuide`, `lib/askGuide.ts`): shown in full in an empty conversation and, at any other time, as a collapsible *What to ask* panel (`GuideToggle`, a button next to the composer with `aria-expanded`). *Questions that work well* are grouped (the project, how things work, relationships, explain code) and each example is a button that **fills the composer and never sends**; the class `X` (the most depended-on non-test class or interface) and the module `y` (most non-test files) come from the graph `useGraph` already caches, with static placeholders (and a note saying so) until it is there. *Questions that won't work, or will waste one of your questions* is a fixed list (off-topic, asking to change code, tests, things not in the code, languages Archyra only counts, "explain everything", other conversations). The honest counting note (`COUNTING_NOTE`) is beside the composer and in the guide, next to the real remaining count from `/usage` (never a literal). `QUESTION_NOT_ANSWERABLE` (422) is shown inline on that turn with the question quoted, "Not counted" in the copy, **no Try again** (the same question would be refused again), the text back in the composer and the guide opened. A `MODULE` source links to the Architecture tab with `?node=`; the `REPOSITORY` source has no link and its excerpt is the README text. **No provider is named anywhere in the frontend:** the backend's provider chain is configuration, so "Answered by X" shows the `providerName` the server sends (`providerNote`, falling back to the free-form `provider` id) and the note says answers come from third-party free-tier AI providers that may log prompts or use them to improve their products. Never switch on a provider id.
- **The initial graph and the name filter** (`spec/graph-default-and-name-filter`). *Default view:* with **no `nodes` and no `edges` parameter** the Architecture tab and the Overview preview open on **modules joined by `DEPENDS_ON`** (no `EXTENDS`/`IMPLEMENTS`), but only when, after the tab's default scope (`working`, which hides test modules), there are at least 2 modules and at least 1 `DEPENDS_ON` edge between two of them; otherwise on `classicDefault` (classes and interfaces with `DEPENDS_ON`/`EXTENDS`/`IMPLEMENTS`, else files and functions), so a single-package repository still opens on its classes. `defaultFilter(graph, scope)` in `components/graph/adapter.ts` is the single source of truth for both tabs (it judges against the tab's *default* scope, so changing the scope filters the same view instead of swapping it). A URL with an explicit `nodes` or `edges` parameter keeps the classic fallback for whatever it leaves out, so old links draw what they always did. While the module default is what is drawn, a caption under the filters says so ("Modules joined by DEPENDS_ON. Turn on Classes to look inside."); the first change to the selection writes a parameter and the caption is gone. No storage, no persisted preference. *Name filter:* `GraphSearch` ("Filter by name", `type="search"`, a Clear button, placeholder "e.g. service") sits in the canvas toolbar (so it is there in full screen) and, in the List view where there is no canvas, in the view bar. It is a case-insensitive substring match on the node's `name` (a module's full name), trimmed, at most 100 characters, applied by `visibleGraph` (`GraphFilter.query`) **on top of the node types and the scope and before the edge check**, so edges show only when both ends do and nothing pulls in a neighbour. `?q=<term>` is left out when empty and written with `replace`; the input updates at once and the URL and layout follow 250 ms later (`SEARCH_DEBOUNCE_MS`); an over-long `q` is read as empty. `/` focuses the field when nothing is being typed in (Architecture tab only), Escape in the field clears it (and does not deselect the node). A selected node the filter hides **stays selected** and the inspector says "Hidden by the filter" with *Clear filter*; a polite live region says "Showing 12 of 87 nodes"; a filter that keeps nothing draws "No classes or interfaces match “…”" over the **still-mounted** canvas (so full screen survives) with *Clear filter* and *Show all* (scope All). **The layout cache key carries the exact visible ids** (`idsKey`), because a filter produces sets of the same size with different members; manual positions (`overlayPositions`) survive filtering and hidden nodes keep theirs. The Relationships tab already had its own list filter (name or file, same case-insensitive substring rule, local state); it is unchanged and no control was added there.
- **Delete account (Settings → Danger zone):** `features/settings/DeleteAccount.tsx` with `useDeleteAccount`, `useRequestAccountDeletion`, `useConfirmAccountDeletion` (`hooks/useAccount.ts`). A *Delete account* button opens a native modal `Dialog` (focus trapped, Escape closes) that lists the consequences (`DeletionConsequences`: repositories, graphs and conversations are deleted permanently; **usage is not reset**, a new account keeps the analyses and questions already used; paid plans are not carried over; only hashed counts are kept) and requires the word `DELETE` typed (`deleteGate.ts`, case sensitive) plus, when `linked-identities.hasPassword`, the password. An account without a password sees "We'll email you a confirmation link" and a sent state; the link opens `/settings/delete-confirm?token=…` (`DeleteConfirmPage`, behind sign-in, token read once and removed from the address bar, **nothing is deleted until the button is pressed**). Copy comes from `describeDeleteError` (`lib/errorCopy.ts`): a wrong password is "Wrong password", not a failed sign-in; `LAST_ADMIN`, `DELETE_METHOD_MISMATCH`, an expired link and `ANALYSIS_IN_PROGRESS` each say nothing was deleted. On success the hooks call `session.endAfterDeletion()` (clears the token and cache the way sign-out does, no second server call, and sets the end reason `deleted`); **`RequireAuth` then sends the visitor to the landing page with the router state `accountDeleted`** (a `navigate` in the hook raced the guard's own redirect to /login, which won), so nothing refetches on a cleared cache (the hydration rule above) and the landing page shows a dismissible "Account deleted" notice. `Dialog` wraps Tab and Shift+Tab itself (a native modal still lets Tab leave to the browser's own interface), so focus stays in every dialog. The emailed-link page reads its token in the `useState` initializer (a pure read: StrictMode runs it twice) and drops it from the address bar in an effect. `scripts/e2e/account-deletion.spec.ts`: the dialog and its gate on the test account, and (opt-in, `ARCHYRA_E2E_DELETE=1` + `ARCHYRA_E2E_MAIL_API`, a MailHog address) a throwaway account that deletes itself, cannot sign in and returns with its usage.
- **Test scope (`scope`):** every graph node, node detail and file carries `test: boolean` (computed by the backend from the path; no premium gate, every plan has it). `components/graph/scope.ts` owns `Working | Tests | All`: `working` hides test code, `tests` is **strict** (only test nodes, and edges only when both ends are tests), `all` shows everything. Each tab owns its own `scope` with its own default: Architecture `working`, Relationships `working`, Files `all`. The param is **left out at the tab's default**, so default URLs stay clean; an unknown value falls back to the default. The adapter (`visibleGraph`) applies the scope **before** the edge check, the layout cache key includes it (a scope change re-lays out, a set seen before hits the cache), the option counts come from `scopeCounts` over the fetched graph, and `ScopeControl` is a keyboard radio group (the help tooltip says what counts as a test). On Relationships only the browse list follows the scope: the detail panel is unfiltered and badges test items, and a deep-linked item the scope hides stays selected with a *Show all* notice. On Files the scope sends `test=false|true` (nothing for `all`), is part of the files query key, resets to page 0, and totals are the server's. The Overview preview follows the Architecture default (`working`, falling back to `all` for a repository that is all tests).
- **Dragging (Architecture):** every node is draggable. `GraphCanvas` keeps its own copy of the nodes (so a drag never re-runs the layout worker or the parent) and reports only *finished* moves (`onMove`: a drop or one arrow-key step) to `useManualPositions(analysisId)`, an in-memory per-session store (never storage or the backend; dropped on reload and when another analysis opens). `overlayPositions` lays the manual positions over the dagre result **after** the layout cache, so filter/scope changes re-lay out the other nodes while moved ones stay put, and hidden nodes keep theirs for when they return. **Reset layout** (toolbar, enabled only when a visible node was moved) clears them and refits. Gestures use React Flow's own props: drag threshold 4px (`nodeDragThreshold`/`nodeClickDistance`) so a click still inspects while a drag, or a Ctrl/Cmd/Shift-click, never changes `?node=`; Shift-drag on empty canvas draws a selection box, Ctrl/Cmd-click toggles a node, dragging any selected node moves the group, Escape clears; arrow keys nudge the selected nodes by 5px (20px with Shift) once focused and selected (React Flow's default; its assertive per-keypress live region is silenced and replaced by one polite message after a burst); touch is one finger on a node to drag, on the canvas to pan, two to pinch (`touch-action: none` on the canvas). `Backspace` never deletes a node (`deleteKeyCode={null}`). Minimap and fullscreen follow the moved positions.

## Rules

- **Components use only hooks** from `src/hooks/`. They never call `fetch` or import `api/http`, `api/endpoints/*` or `api/session` (ESLint enforces it). Every query key lives in `api/queryKeys.ts`; the graph key carries every `/graph` parameter, present or not.
- **No mocks, ever.** No mock client, fixture data, MSW, simulators, dev mock panels or `VITE_API_MODE` switches in `src/`. The only allowed inputs are small inline values inside `*.test.ts(x)` for pure logic. Types are hand-written from the backend DTOs and confirmed with `probe-api.mjs`; if the backend lacks something, report it instead of inventing data.
- **Session:** the access token lives in module memory only (never storage, URLs or logs). Refresh and logout send `X-XSRF-TOKEN` from `GET /auth/csrf`. Refresh is single-flight: two parallel refreshes would replay the rotating cookie and revoke the login family.
- **Errors** are handled by `code` through `lib/errorCopy.ts`, never by message text. API strings render as text only; links only from validated values.
- **Admin gating:** the Admin link and every `/admin/**` route exist only when `GET /users/me` returns role `ADMIN`. Everyone else, anonymous visitors included, gets the ordinary 404 screen. A `403 ACCESS_DENIED` from an admin call refetches `/users/me`. The backend enforces access regardless.
- **Locked features, three states:** available; PRO-locked (`ProLocked`, opens the upgrade dialog; also on `403 PREMIUM_FEATURE`); coming soon (`ComingSoon`, never calls the backend). Decide by reading the backend. Today nothing is PRO-locked: the premium graph parameters exist only as a gate and return the same graph.

## Design

- Theme: Hallmark **Coral**, light only. **`Blueprint` and blueprint/engineering-grid aesthetics are banned**: no cyan or blue drafting paper, no grid, cross or dot pattern on any page, canvas or image (never render React Flow's `<Background>`), no drafting motifs.
- **Tokens:** every colour and font is a token in `src/styles/tokens.css`; Tailwind reads them through `@theme inline reference` in `index.css`, with the stock palette removed. `npm run check:tokens` fails on any hex, `rgb()`/`hsl()`/`oklch()`, font-family literal, font name or stock Tailwind colour class elsewhere in `src/`.
- Graph node and edge styles are defined once in `components/graph/graphStyles.ts`, keyed by type; the legend, minimap and canvas read from it. Colour is never the only signal (glyph shapes, dash patterns, markers).
- CSS files carry the Hallmark stamp in their first lines. Run `node ~/.claude/skills/hallmark/scripts/sloplint.mjs src --scope app` (and the landing with `--url http://localhost:5173/ --render`) before shipping UI changes.

## Assets

Images live in `src/assets/` as PNGs produced by `npm run assets:capture` from the real app (Chromium, 2x, a real spring-petclinic analysis by a test account; never admin screens, settings, menus or emails). Import them with static Vite imports; replacing an image means overwriting the file with the same name. Containers size images with `aspect-ratio` and `object-fit`, so new dimensions do not break layouts. `src/assets/README.md` lists every file.
