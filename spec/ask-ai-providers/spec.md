# Spec: Ask AI provider chain

Generalises the Ask AI provider layer from "Gemini, then Groq" to a configurable chain of free LLM providers (candidates from <https://github.com/mnfst/awesome-free-llm-apis>, re-read on 2026-11-19). Scope: `backend/.../ai/llm`, its configuration, its tests, the provider id/name in the chat API, one admin endpoint, and the frontend copy that names providers. **Not touched:** retrieval, grounding, conversations, quota and refund logic.

Read with `Architecture.md` → Ask AI, `backend/spec/ask-ai-backend/spec.md` and `frontend/spec/ask-ai-frontend/spec.md`. Where a rule here is binding it says so.

## 1. Research findings (2026-11-19) that shaped the decisions

| Provider | Verified | Consequence |
| --- | --- | --- |
| Gemini | Free-tier limits are no longer published (README); free-tier prompts may be used to improve Google products; the terms require paid services when the API client is exposed to EEA/Swiss/UK users | Keep the dedicated, tested Gemini adapter (no OpenAI-compatible variant needed). Document the EEA term and the data use |
| Groq | OpenAI-compatible base `https://api.groq.com/openai/v1`; `openai/gpt-oss-120b` free: 30 RPM, 1K RPD, 8K TPM, 200K TPD; 429 carries `retry-after` | Small context budget kept |
| OpenRouter | Free variants end in `:free`; 20 RPM, 50 RPD (1,000 once ≥10 credits ever bought); 429 may carry `Retry-After`; errors can arrive inside a 200 body; README: free providers may log prompts for training | Refuse to start without `:free`; daily cap 50; parse errors in 200 bodies |
| Cloudflare Workers AI | OpenAI-compatible `.../accounts/{account_id}/ai/v1`; 10,000 neurons/day, reset 00:00 UTC, exceeding fails the request (no billing); about 26.7 neurons per 1K input and 204.8 per 1K output tokens for llama-3.3-70b | Account id is part of the base URL; daily request cap derived from neurons |
| Z AI | International base `https://api.z.ai/api/paas/v4` (OpenAI SDK documented against it); 1 concurrent request (README; the limits page itself could not be read); `thinking.type` can be `disabled`; reasoning arrives in `reasoning_content` | `max-concurrent=1`; thinking disabled through `extra-body` |
| Cohere | Compatibility base `https://api.cohere.ai/compatibility/v1` (the audio example uses `.com`); `reasoning_effort` only `none`/`high`; trial key: 1,000 calls/month, 20 RPM, non-commercial (README) | No `reasoning_effort` sent; monthly cap 1000; startup warning |
| OVHcloud AI Endpoints | Anonymous: 2 RPM per IP per model (429 beyond it). With a key: 400 RPM, but the Public Cloud project must have a payment method, so keyed use is billed | Anonymous only: **no `Authorization` header is ever sent**; RPM 2 |
| LLM7 | Base `https://api.llm7.io/v1`; the docs ask for a token (dash.llm7.io), the README says token.llm7.io and that anonymous use worked on 2026-08-21; free token: 60 RPM, 100K tokens/24 h; no privacy statement found | Needs a key to be in the chain; daily cap from the token budget; marked unverified |
| NVIDIA NIM | Hosted endpoints for prototyping; use is logged to improve NVIDIA products; "do not submit personal or confidential data" | Off by default |

It would be one config block; left out of scope.

## 2. Decisions

1. **One generic `OpenAiCompatibleChatProvider`**, driven entirely by configuration, replaces the Groq class and serves every OpenAI chat-completions provider. It uses Spring's `RestClient` directly (not the OpenAI SDK) because the safety rules need exact control of the headers (OVH must receive no `Authorization` header at all), of the error classification (status and `Retry-After` only, never a body) and of the response parsing (`content` only, reasoning fields ignored). Gemini keeps its dedicated Spring AI adapter. **Adding a provider is one config block** (plus its id in `order`).
2. **Configuration** (all in `application.properties`, keys from the environment, a missing key never fails startup, a provider without a key is not in the chain):
   `archyra.ai.providers.order`, `.max-attempts` (default 4), `.cooldown-default`, `.cooldown-max` (1 h), `.cooldown-misconfigured`, `.min-attempt-timeout`, and per provider `archyra.ai.providers.<id>.{protocol, enabled, display-name, base-url, api-key, auth, model, max-context-tokens, requests-per-minute, max-concurrent, max-requests-per-day, max-requests-per-month, logs-prompts, reasoning-effort, extra-body}`. `0` means "no local limit". A provider is read by id with the `Binder` because `order` and `max-attempts` live beside the id blocks.
3. **Tiers.** Standard (in the chain when its key is set): `gemini, groq, openrouter, cloudflare, zai, cohere, ovh, llm7`. Opt-in (`enabled` must be explicitly `true`; a startup warning names them): `nvidia-nim, kilo, gonka`. A tier-2 provider that is enabled but not listed in `order` is appended after the listed ones. OVH has no key: it is the one standard provider that is in the chain without one (anonymous mode), and `OVH_ENABLED=false` removes it. A base URL with an empty path segment (`.../accounts//ai/v1`, a missing Cloudflare account id) makes a provider "not configured".
4. **Safety rules, in code and tested.**
   - OpenRouter refuses startup (`IllegalStateException`, clear message) when its model id does not end in `:free`.
   - OVH is anonymous only: `auth=none` is forced for it, a configured key is ignored with a warning, and the `Authorization` header is never sent. (Re-verified: keyed use needs a payment method.)
   - Cohere logs a startup warning (non-commercial).
   - A key is only ever sent to the provider whose block holds it. Two active providers holding the same key value refuse startup (a copy-paste mistake would send one provider's key to another).
   - Keys never appear in logs, exception messages, `toString`, the admin endpoint or any API response.
5. **Local protection per provider** (`ProviderGuard`): a Bucket4j token bucket for requests per minute, a semaphore for `max-concurrent` (released when the call really ends, also after a gateway timeout), and in-memory counters for UTC-day and UTC-month requests. A restart resets the counters; that is accepted because the provider's own 429 then triggers the cool-down. A local refusal skips to the next provider and is **not** an attempt. Context budgets are per provider (`max-context-tokens`), conservative, derived from the provider's tokens-per-minute or neuron limits.
6. **Failures.** Same fallback triggers as before (429, 5xx, timeout, connection error, empty or blocked answer, bad key) plus `404` (model not found). Cool-down escalates: the first 429 uses `Retry-After` (or `cooldown-default`), a repeated 429 doubles the previous duration (never less than `Retry-After`) up to `cooldown-max`; a success resets it. A bad key (401/402/403) or a missing model (404) starts a long cool-down (`cooldown-misconfigured`) with an `ERROR` log and never crashes. The pre-flight check refuses before charging when no provider is usable (configured, not cooling down, not locally exhausted). Attempts per question are bounded by `max-attempts`; each attempt gets `remaining / min(providers left, attempts left)`, never less than `min-attempt-timeout` and never more than connect + read, all inside `timeout.total`. Refund rules are unchanged: refund only when every attempt failed.
7. **Output normalisation** (every provider, Gemini included): `<think>…</think>` blocks (and an unterminated trailing one) are removed, reasoning fields (`reasoning_content`, `reasoning`) are never read, the text is trimmed, an empty text or a `content_filter` finish is a provider failure (`EMPTY`). An `error` object in a 200 body is classified like the HTTP status it carries. Citation parsing and Neo4j source verification run unchanged on the cleaned text.
8. **Identity.** `provider` becomes a free-form id (`gemini`, `groq`, `openrouter` …, lower case); `chat_messages.provider` is `varchar(40)` without an enum (a startup step widens the old column, drops the old check constraint and lower-cases old rows). `providerName` (the display name, resolved from configuration at read time, the id when the provider is no longer configured) is added to the chat response and to message items.
9. **Ops.** `GET /api/v1/admin/ai/providers` (ADMIN, re-checked against the database like the other admin routes) returns, per known provider: `id, displayName, configured, enabled, state (AVAILABLE | COOLING_DOWN | RATE_LIMITED_LOCALLY | DISABLED), coolingUntil, requestsToday, requestsThisMonth`. No key, no key fragment, no URL.
10. **Frontend.** No hard-coded provider names. "Answered by X" uses `providerName`. The data-use note beside the composer says: answers are generated by third-party free-tier AI providers, which may log prompts or use them to improve their products, and questions and code excerpts are sent to them. Everything else is unchanged.

## 3. Data-use stance

The chain sends repository text (public repositories only) to third parties on free tiers. Some log or train on it. That is disclosed in the UI note, in `README.md` and in `Architecture.md`. Providers that state logging for training and are not otherwise essential (NVIDIA NIM, Kilo) are off by default. `logs-prompts` records what a provider's terms say; it drives a startup warning for enabled providers that log.

## 4. Tests

WireMock as the fake servers, no mocks of our own code, latches not sleeps. Chain order and fallback across 3+ providers in one request; `max-attempts`; total timeout; no key → skipped; no keys at all → `AI_UNAVAILABLE` and no charge; RPM bucket and `max-concurrent`; daily/monthly counters; escalating cool-down; pre-flight refusing before charging; refund exactly once when all fail; OpenRouter non-`:free` refuses startup; OVH never gets an `Authorization` header; tier-2 inactive without `enabled=true`; `<think>` stripping; empty completion is a failure; citations still verified; admin endpoint ADMIN-only without secrets; opt-in live smoke tests per provider (`ARCHYRA_AI_LIVE_TESTS=true` plus that provider's key; skipped silently without it); frontend unit test of the provider-name display.
